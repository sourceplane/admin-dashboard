# admin-dashboard — risks and open questions

| ID | Risk | State | Notes |
|---|---|---|---|
| AD-A | `baseline-v1` is not yet proven live | OPEN | Proven offline in Baseline CI: the offline bootstrap with the blueprint's own hooks, the lanes' own steps in staged job trees (the migrations applied through a stand-in Supabase Management API over a real Postgres with Supabase's roles), and the built Worker served by `wrangler dev` over it. A live bootstrap needs a workspace with Cloudflare and Supabase connected and room for two Supabase projects (AD-E) |
| AD-B | Node.js proxy on OpenNext | ACCEPTED | `opennextjs-cloudflare build` says Node.js middleware support is experimental and not maintained by OpenNext. ai-chatbot runs the same shape; the e2e tier serves every page through it, eight concurrent first requests included |
| AD-C | `next-auth` 5.0.0-beta.25 under Next.js 16 | ACCEPTED | The template's pin; its peer range stops at Next.js 15, and pnpm warns. `tests/web` drives its real handlers and the e2e serves its sessions; ai-chatbot runs the same pair. A later beta (≥ 5.0.0-beta.30) admits 16 and is a deliberate bump |
| AD-D | The GitHub OAuth App's secret is in the server bundle | ACCEPTED | `next build` inlines `AUTH_GITHUB_SECRET` into the Worker's script, so anyone who can read the account's Workers scripts can read it — the same boundary as the cms-contentful tokens. A composition that pushes runtime secrets would move it into a Worker secret |
| AD-E | Two Supabase projects per product | ACCEPTED | Stage and prod are a project each; the free plan allows two active projects per organization. BOOTSTRAP.md lists it as a prerequisite |
| AD-F | The product photos are on Vercel Blob | ACCEPTED | The seed keeps the template's image URLs, as the reference keeps its avatars on Contentful's CDN. If they go, the photos break and nothing else does; any product's own photos replace them |
| AD-G | Hyperdrive's read cache | ACCEPTED | A product changed in the SQL editor shows within about a minute. The dashboard writes nothing (upstream's delete is commented out), so it never reads back its own write |
| AD-H | The session key lives in the database | ACCEPTED | Generated by `040_app_secrets` in `app_private`; whoever can read the database can forge a session. An `AUTH_SECRET` Worker secret overrides it |
| AD-I | stack-tectonic 0.19.0, not 0.20.0 | ACCEPTED | 0.20.0's lane-shared install links `node_modules` out of the job's tree, which Turbopack refuses (`intent.yaml` says why) |
